# Todo — Motion spec

Уся анімація в Todo тримається на одній кривій **ease-out** `cubic-bezier(0.22, 1, 0.36, 1)` і трьох тривалостях: 130–220 мс для дрібниць, 320–380 мс для переходів, 460 мс для зуму календаря. Тут описано кожну анімацію: що рухається, звідки, скільки мс і з якою кривою, а в кінці є нотатки для реалізації на .NET.

## Принципи

- **Одна крива.** Вхід завжди на `ease-out` (швидкий старт, м'яка зупинка). Вихід на `ease-in`, і він коротший за вхід.
- **Напрямок має сенс.** Глибше в календар — наближення від точки кліку. Вище — віддалення. Наступний період — зсув справа, попередній — зліва. Нижчий пункт сайдбару — виїзд знизу.
- **Малі відстані.** Зсуви 6–40 px, масштаб 0.86–1.14. Нічого не «літає» через весь екран.
- **Рухаються лише `opacity`, `transform`, `filter: blur`.** Розміри й layout не анімуються (виняток — ширина смужок прогресу).
- **Вихід не блокує.** Старий екран зникає за ≤130 мс, новий вмикається одразу після цього.

Нотація: `0→1` означає «з → в», `±` означає, що знак залежить від напрямку, `E` — головна крива, `EI` — `ease-in`.

## Токени

У коді таймінги мають братися лише з цих констант, а не з «магічних чисел» по коду.

| Токен | Значення | Де використовується |
|---|---|---|
| `Ease.Out` (E) | cubic-bezier(0.22, 1, 0.36, 1) | Усі входи, зсуви, індикатори, тумблери |
| `Ease.In` (EI) | ease-in = cubic-bezier(0.42, 0, 1, 1) | Вихід екрана, закриття діалогу |
| `Ease.Std` | ease = cubic-bezier(0.25, 0.1, 0.25, 1) | Hover, зміна кольору/фону |
| `Dur.Hover` | 150–200 ms | Hover-фони, кольори кнопок |
| `Dur.Exit` | 130 ms (екран), 150 ms (діалог) | Вихід старого стану |
| `Dur.Pop` | 180 ms | Поповери (Date, Time, Priority, Tag) |
| `Dur.Check` | 200–300 ms | Чекбокс, закреслення, затемнення задачі |
| `Dur.Dialog` | 220 ms (тінь), 320 ms (вікно) | Відкриття New task |
| `Dur.Slide` | 340 ms | ‹ › стрілки, Today, вкладки Settings, зміна сайдбару |
| `Dur.Section` | 130 ms вихід + 380 ms вхід | Inbox ↔ Today ↔ Calendar |
| `Dur.Indicator` | 380–420 ms | Підсвітка сайдбару, повзунок Year/Month/Week/Day |
| `Dur.Zoom` | 460 ms | Year → Month → Week → Day і назад |
| `Dur.Progress` | 500 ms | Ширина смужок прогресу дня/місяця |
| `Dur.Launch` | 520 ms | Перша поява контенту при старті |

## Навігаційні переходи

Усі переходи анімують **область контенту** (панель під шапкою). Заголовок сторінки (h1) щоразу додатково робить `opacity 0→1, translateY 6→0 px`, 360 ms, E. Шапка вікна і сайдбар стоять на місці.

| Перехід | Тригер | Вихід старого | Вхід нового | Час, крива |
|---|---|---|---|---|
| Зум углиб | Клік по місяцю / тижню / дню, Year→Day у перемикачі | Миттєва заміна | opacity 0→1, scale 0.86→1, blur 6→0 px | 460 ms, E |
| Зум назовні | Хлібні крихти, Day→Year у перемикачі | Миттєва заміна | opacity 0→1, scale 1.10→1, blur 6→0 px | 460 ms, E |
| Наступний / попередній період | ‹ ›, Today, вкладки Settings | Миттєва заміна | opacity 0→1, translateX ±32→0 px (вперед = справа) | 340 ms, E |
| Розділ сайдбару | Inbox ↔ Today ↔ Calendar | opacity 1→0, translateY ∓10·dir px, 130 ms, EI | opacity 0→1, translateY 18·dir→0 px | 380 ms, E |
| Вхід у Settings | Кнопка Settings | Миттєва заміна | контент як «зум углиб» (origin 50% 30%), новий сайдбар translateX 16→0 + fade | 460 / 340 ms, E |
| Вихід з Settings | «← Back to app» | Миттєва заміна | контент як «зум назовні», сайдбар translateX −16→0 + fade | 460 / 340 ms, E |
| Згортання сайдбару | Кнопка в шапці сторінки | — | width 232→0 px, opacity 1→0 (і навпаки) | 340 ms E, opacity 220 ms |
| Старт застосунку | Запуск | — | opacity 0→1, translateY 12→0 px | 520 ms, E |

> Примітка: у фінальному дизайні сайдбар згортається не в 0, а в «рейку» 56 px з іконками (підписи згасають за 180 ms). Джерело істини для розмірів — `design-reference.dc.html`.

**Точка зуму.** `transform-origin` — центр елемента, по якому клікнули, у відсотках від області контенту: `x = (rect.centerX − body.left) / body.width`, так само для y. Якщо кліку не було (перемикач, клавіатура), береться `50% 40%`.

**Напрямок розділів.** Порядок: Inbox = 0, Today = 1, Calendar = 2, Settings = 3. Якщо новий індекс більший, `dir = +1` (новий екран виїжджає знизу), інакше `dir = −1`. Вхід стартує тільки після завершення виходу, а анімацію виходу треба скасувати перед входом, інакше вона тримає opacity 0.

**Індикатори.** Підсвітка активного пункту сайдбару — один прямокутник, що їде `top`, 380 ms, E (крок 33 px = 32 висота + 1 gap). Повзунок Year/Month/Week/Day їде `translateX` кроком 64 px, 420 ms, E; колір тексту кнопок 250 ms. На Inbox, Today і Settings повзунок схований (opacity 0, 250 ms).

## Мікровзаємодії

Дрібні реакції тривають 150–300 ms і не зсувають layout. Зміна стану задачі має одразу відображатись у всіх видах.

| Елемент | Що змінюється | Час, крива |
|---|---|---|
| Чекбокс (виконано) | фон і рамка #66666E → акцент; галочка opacity 0→1 | 250 ms / 200 ms, Std |
| Назва задачі | колір #EDEDEF → #8C8C92; закреслення завжди є, анімується його колір transparent → #8C8C92 | 300 ms, Std |
| Нова задача в списку | opacity 0→1, translateY −8→0 px (лише для щойно створеної або перенесеної «→ Today») | 360 ms, E |
| Фільтр за тегом | задачі інших тегів: opacity 1 → 0.3 | 300 ms, Std |
| Смужка прогресу (день, місяць, Today) | width до нового % | 500 ms, E |
| Тумблер у Settings | трек #2A2A2F → акцент (200 ms); кнопка їде на 16 px | 250 ms, E |
| Перемикачі-сегменти | фон і колір активного сегмента | 200 ms, Std |
| Hover кнопок і пунктів меню | фон rgba(255,255,255,0.04–0.06) | 150–180 ms, Std |
| Hover картки задачі | фон #17171A → #1C1C20 | 180 ms, Std |
| Hover багатоденної смуги та блоку розкладу | brightness 1 → 1.2 | 200 ms, Std |
| Hover заголовка дня / місяця | opacity 1 → 0.75 | 200 ms, Std |
| Зміна акценту та прозорості в Settings | фон вікна та акцентні елементи наживо | 300 ms, Std |

Закреслення не додається і не прибирається: воно завжди є в тексті, а анімується його колір. Так воно плавно «проявляється» без стрибка тексту.

## Оверлеї

Вікно задачі (New / Edit task) відкривається за 320 ms і закривається за 150 ms; поповери з'являються за 180 ms і зникають миттєво.

| Елемент | Відкриття | Закриття |
|---|---|---|
| Тінь за вікном (rgba(5,5,6,0.6) + blur 3 px) | opacity 0→1, 220 ms, ease-out | opacity 1→0, 150 ms, EI |
| Вікно задачі | opacity 0→1, translateY 10→0 px, scale 0.97→1, 320 ms, E; потім фокус у поле назви | opacity 1→0, translateY 0→6 px, scale 1→0.98, 150 ms, EI; дані зберігаються і вікно зникає тільки після кінця анімації |
| Поповер (Date, Time, Priority, Tag) | opacity 0→1, translateY −4→0 px, scale 0.98→1, 180 ms, E; origin — верхній лівий кут під кнопкою | Миттєво (вибір, Done, Esc, інша кнопка, фокус у назву) |
| Клітинка календаря | hover: рамка 1 px #4A4A52, 150 ms | вибір: фон → акцент, 150 ms; діапазон багатоденної задачі — суцільна смуга акценту 15% |

### Барабан часу (як на iPhone)

- **Розміри.** Два стовпці: години 00–23 і хвилини 00–55 з кроком 5. Висота рядка 34 px, видно 5 рядків (170 px), відступи зверху й знизу по 68 px, щоб перший і останній елементи ставали по центру.
- **Прилипання.** Кожен елемент прилипає до центру (snap, mandatory). Вибране значення = round(scrollTop / 34).
- **Фіксація.** Значення записується в стан, коли прокрутка стоїть 120 ms. Під час прокрутки стан не змінюється.
- **Клік по числу.** Плавно прокручує до нього (smooth scroll до index · 34).
- **Вигляд.** Смуга вибору — нерухомий прямокутник по центру (фон 7% білого, радіус 8). Верх і низ стовпця зникають через маску: прозорий 0% → непрозорий 32%–68% → прозорий 100%.
- **Вибране число.** 15 → 19 px, #8C8C92 → #EDEDEF, 200 ms.
- **При відкритті.** Обидва стовпці миттєво ставляться на поточний час, без анімації. Прокрутка барабана сама вмикає «Set time».

## Реалізація на .NET

Реалізуй кожну анімацію через один сервіс `Motion` з токенами вище. Таймінги не розсипай по XAML.

```csharp
public static class Motion
{
    // cubic-bezier(0.22, 1, 0.36, 1)
    public static readonly Vector2 OutP1 = new(0.22f, 1f), OutP2 = new(0.36f, 1f);
    public static readonly Vector2 InP1  = new(0.42f, 0f), InP2  = new(1f, 1f);
    public const int Hover = 180, Exit = 130, DialogExit = 150, Pop = 180, Check = 250,
                     DialogIn = 320, Slide = 340, Section = 380, Indicator = 380,
                     Zoom = 460, Progress = 500, Launch = 520;
    public static TimeSpan Ms(int ms) => SystemAnimationsEnabled ? TimeSpan.FromMilliseconds(ms) : TimeSpan.Zero;
}
```

- **UI-фреймворк.** Оригінальна специфікація наводила приклади для WinUI 3 (Composition API) та WPF (Storyboard + KeySpline). Проєкт будується на Avalonia — ті самі принципи: анімуй `Opacity` і transform (translate/scale) на рівні композиції, а не `Margin`/`Width`; точка зуму = центр трансформації. Blur у зумі необов'язковий: якщо він дорогий, без нього можна обійтися.
- **Послідовність секцій.** Спочатку вихід (130 ms), після завершення підміни контент, зупини анімацію виходу (щоб вона не тримала opacity 0), і тільки тоді запускай вхід. Новий клік під час анімації скасовує попередню.
- **Барабан.** Скрол-контейнер з обов'язковим прилипанням до елемента або власний контрол з інерцією. Фіксуй значення після 120 ms тиші.
- **Вимкнені анімації в Windows.** Якщо в системі вимкнено анімації (Settings › Accessibility › Visual effects › Animation effects), усі тривалості = 0. Зміна кольору та прозорості лишається миттєвою.
- **Продуктивність.** Ціль 60 fps на екрані тижня з ~40 картками. Під час анімації контенту не перебудовуй візуальне дерево повторно.
