# Decisions

One line per decision, newest last. Format: **topic** — decision (reason).

- **Design source** — `docs/design/design-reference.dc.html` is the prototype's `Main.dc.html` taken from the published "Todo for Windows" design artifact (the repo did not contain it); the other boards only set `start-view`.
- **.NET SDK install** — SDK 11.0.100 installed from Microsoft's Debian 12 package feed (packages.microsoft.com) because `builds.dotnet.microsoft.com` / `dot.net` downloads are blocked by the VM's network allowlist.
- **Solution format** — classic `Doba.sln` (the brief names it) rather than the new `.slnx` default.
- **Test runner** — Microsoft Testing Platform (`global.json` `test.runner`), required by the .NET 10+ SDK for xunit v3 projects.
- **xunit version** — `xunit.v3.mtp-v2` 3.2.2, not 4.x: `Avalonia.Headless.XUnit` 12.1.6 is compiled against xunit.v3 3.2.2 and fails discovery with `MissingMethodException` under 4.0.3. All test projects use the same version.
- **CA1716 off** — VB-keyword clash warnings (`Get`, `Date`, `To`) are noise in a C#-only codebase.
- **Avalonia telemetry** — `AVALONIA_TELEMETRY_OPTOUT=1` in CI and docs; the app itself makes no network calls.
- **Ids** — `long` ids assigned by the store as max existing Id + 1; Id order replaces the prototype's array order as the final sort key (a deleted newest Id may be reused, which is harmless for upsert persistence).
- **Durations** — `DurationMinutes = 0` means "unspecified"; the timeline treats it as 30 min (prototype `dur || 30`); the dialog defaults to 60.
- **Week numbers with Sunday start** — label = ISO week of the Monday inside the displayed 7-day week.
- **Name** — "Doba" replaces the design's working title "Todo" everywhere (title bar, settings footer "Doba 0.1 · local only", data folder `%LOCALAPPDATA%\Doba`).
- **Storage writes** — single background writer over an unbounded Channel; bursts commit in one transaction; a burst that fails on a per-row error (constraint, bad argument) is replayed op-by-op, one refused by the database as a whole is not (see "Writer failures"); errors surface from the next `FlushAsync` / `WriteFailed` event.
- **Storage reads** — `Load()` reads tasks through SQLitePCL's low-level API (halves 10k load time vs SqliteDataReader).
- **JSON enums** — camelCase strings (`"asap"`, `"sunday"`); import validates and reports JSON paths in `FormatException`.
- **P/Invoke style** — platform code uses `DllImport` with only blittable signatures (no strings, no SetLastError) instead of `LibraryImport`, avoiding `AllowUnsafeBlocks`; under NativeAOT these bind directly with no marshalling stubs.
- **Hotkey / setting-change messages** — received by Doba's own hidden window rather than Avalonia's `Win32Properties.AddWndProcHookCallback`, whose shared callback chain lets the last subscriber overwrite earlier results (e.g. title-bar hit testing).
- **Autostart** — HKCU Run value `Doba` = `"<exe>" --minimized`; the app starts hidden in the tray with that flag.
- **Overdue span label across months** — "28 Oct – 2 Nov" (the prototype would print "28–2 Nov").
- **Tag normalisation** — whitespace left after stripping '#' is trimmed ("# deep work" → "deep-work").
- **Store no-ops** — mutations of unknown Ids and identical updates raise no event and write nothing.
- **Golden tests** — Core projections are checked against fixtures generated by running the prototype's own script under Node; fixtures are committed so tests do not need Node.
- **No stock theme** — no Fluent/Simple theme package; base templates for the few stock controls we use are ours (`Theme/Controls/Base.axaml`).
- **Animator** — content animations are explicit composition animations (opacity, translation, scale offsets from layout); cancel/reset always restores opacity 1 and identity. Zoom blur not implemented (optional in the spec).
- **Hover brightness(1.2)** on bars/blocks is approximated with a 4 % white overlay. (The dialog backdrop's 3 px blur, first left out, is now reproduced: see "Backdrop blur behind overlays".)
- **Own ToggleSwitch** — subclass of ToggleButton so the knob moves by render transform, not layout.
- **CI cost** — owner asked for minimal GitHub Actions use: one windows-latest job, triggered only by `workflow_dispatch` or a pull request to main (docs-only changes skipped), concurrency-cancelled, 30-min timeout; Linux build/test/screenshots run locally in the dev VM instead.
- **Import** replaces all tasks, tags and settings with no confirmation (the design has none); result/error shown inline under "Export & import".
- **Theme "System"** is stored but rendered as Dark (no light palette yet).
- **Strike-through** — Avalonia cannot bind a TextDecoration stroke brush per state cheaply, so done titles toggle the strike and fade the text colour (Motion.Strike); the strike line itself does not fade from transparent.
- **Inbox virtualisation** — per-group ItemsControls with VirtualizingStackPanel inside one page ScrollViewer (Avalonia 12 virtualises against the effective viewport), so both columns still scroll together as designed.
- **Week fit measurement** — the view reports each row's height; card heights come from shaping the title with the real font at the real column width (≤2 lines), per density; Core's `WeekMetrics.CardHeight` receives the measured map, keyed by title (the tallest card of a title wins). Core also accepts a per-task `WeekMetrics.TaskCardHeight` (title, tag, time, priority) with the title function as fallback; the App does not pass it yet.
- **Week compact** — compact density shows as many cards as actually fit (the prototype's compact render reuses its fixed 403 px heuristic).
- **Windows-first from 2026-11-18** — the build continues on the owner's Windows 11 PC, so build, tests, headless screenshots, NativeAOT `win-x64` publish and `--perf` are all run locally; the local AOT smoke is `win-x64`, not `linux-x64`.
- **No extra Actions runs** — owner's instruction: test everything locally. No `workflow_dispatch` runs; the single CI run is the one the final pull request into `main` triggers.
- **Overlays are in-window panels** — the task dialog, its popovers and the search palette are hosted by `Shell/OverlayHost` inside the main window, not Avalonia `Popup` windows: headless frame capture does not include popup top-levels, and one window keeps focus handling simple.
- **Screenshot writing is opt-in** — tests write PNGs to git-ignored `artifacts/screenshots/` unless `DOBA_SCREENSHOTS=1`, which refreshes `docs/screenshots/` (parallel worktrees would otherwise rewrite tracked binaries on every test run).
- **Sidebar collapsed state** is kept in memory only (the prototype does not persist it either). `AppSettings` has no `SidebarCollapsed`; a `sidebarCollapsed` value in an older export or settings table is ignored.
- **Search hits** always open the task's edit dialog; the palette never navigates.
- **Content swap** — `MainViewModel` raises `Navigated`, then hands the swap to `ContentSwapper`, which the window points at `ShellComposition.Transitions.Run`; screen, header and sidebar all change inside the swap, so on section transitions the title changes with the content (as in the prototype).
- **Screen views are cached** — a screen's view is created on first visit and then kept in the tree with `IsVisible=false`, so a transition never rebuilds a visual tree.
- **Overlays** — opening an overlay while one is open replaces it at once (search hit → edit dialog); clicking the shade does nothing (the prototype's shade has no handler); focus moves into the overlay after its first layout and returns to the element that had it, or to New task if that is gone. Focus returns after `OnClosed` has written the store (see "Overlay focus return").
- **Shell keys** — N only when no overlay is open, no text box has focus and New task is visible; Ctrl K ignored while an overlay is open.
- **Caption buttons** carry Avalonia's window-decoration element roles and also plain click handlers; maximise keeps one glyph (the design has no restore glyph).
- **Backdrop glows** — the design's three blurred blobs are painted as radial falloffs calibrated against the reference pixels; nothing is blurred at run time.
- **Header title** — title and subtitle are two text blocks (Avalonia applies letter-spacing per block); offsets were measured against the reference and stored as `Space.Shell.*` tokens.
- **Add-tag row in the rail** — collapsing the sidebar while the tag input is open creates a non-empty name (same as losing focus); in the rail "+" is disabled.
- **Many tags** — the tag list scrolls so Collapse/Settings stay pinned at the bottom (the prototype clips).
- **Sidebar counts** are always shown, including 0, and never dimmed by the tag filter.
- **Settings tab label** — the sidebar says "Shortcuts", the page title says "Keyboard shortcuts" (both as in the prototype).
- **Month cells** are reconciled by week position and column, not by date, so changing month updates ~42 cells in place.
- **Month "+N more", chips and bars** are not interactive on their own; the click goes to the day cell (prototype: `pointer-events: none`).
- **Month geometry** used by both the projection and the view (26 header, 40 W-column, 34 day number, 24 lane) lives in `Screens/Month/MonthLayout.cs`.
- **Day rows** — Day span rows and cards are their own controls (`DaySpanRow`, `DayCard`): the Day design's sizes and two-row card differ from the week bar and card.
- **Day "Add task"** passes the shown day and is labelled just "Add task" (the prototype's `addLabel` is unused in its markup).
- **Time wheel emphasis** — the selected number is laid out at 19 px once per commit and the 15→19 growth is a render-transform scale, so nothing is re-laid out per frame; emphasis follows the committed value, not the row passing under the band.
- **Time wheel commit** — fires after 120 ms of stillness following a user move, even if the index ends up unchanged (in the prototype any scroll switches on "Set time"); the 120 ms wait is not an animation and stays when OS animations are off; a pending commit is flushed if the wheel is removed (quick "Done"). Smooth scrolling uses `Motion.Slide`; no fling momentum.
- **Reference PNG vs prototype source** — where a reference image shows an artefact of how the prototype was rendered (Month span bars drawn as loose text under the row, Week column separators and the next-week hatch missing, no scrollbars in headless Chromium), the prototype source wins.
- **Text rendering** — every window draws text with grayscale antialiasing and no hinting, like the prototype (`-webkit-font-smoothing: antialiased`). Glyph boxes match the references to the pixel; our stems still carry a little more ink (Skia's text gamma, not configurable in Avalonia 12.1.6). Font weights are not altered to compensate.
- **Whole-pixel layout** — Avalonia rounds each measured size up where Chromium carries fractions, so a few stacks land 1 px off the reference (Inbox/Today section rhythm, 4th Day card onward, settings rows 71 vs 70.7 px, key caps 19 vs 18.3 px). Accepted rather than fudged with per-element offsets.
- **Segmented controls and text buttons** come out 1–2 px wider than the reference when they hold several labels (each label's width rounds up to a whole pixel); unrounded text layout would blur the pill edges, so this stays.
- **Checkbox ring** — the CSS 1.5 px ring is snapped down to whole device pixels (1 px at 100 %), as Chromium paints it.
- **Strike-through** — `StrikeText` paints its own always-present 1-device-px line on a whole pixel row and only animates its colour (replaces the earlier "toggle the decoration" decision wherever `StrikeText` is used).
- **Glyph centring** — icons and the priority glyph round half-pixel centring offsets up, as Chromium does.
- **Calendar track edges** — column edges at `round(i·W/n)`, row edges at `floor(j·H/m)`, reproducing the reference's snapping.
- **Month rows** use the measured body height − 4 px (the prototype hard-codes 832 inside an 836 px body); when a week row leaves under 26 px below its lanes, the cell shows "+N more" for all its tasks in the day-number row. The rule is also in Core (`MonthMetrics.MinListRoom`, `MonthDayCell.MoreInHeader` with no items and `MoreCount` = all tasks); the App still computes it itself from the same numbers. A Month body shorter than its header gives row height 0.
- **Week cards** — titles break only between words; when tag + time would leave the title under 80 px the tag is hidden (priority and time stay) and "+N more" fitting uses the same rule. The screen builds no cards before its first measure pass. Cells are reused across week changes.
- **Space** completes the focused task from any button of a list row or week card (the checkbox keeps its native Space); Enter keeps the focused button's own action; key repeat does not toggle again.
- **Today schedule aside** scrolls on its own when the content area is shorter than the 812 px timeline, first centred on the now-line; at 1600×1000 it does not scroll.
- **Now-line** is shown only between 07:00 and 23:00; outside the grid it is hidden, not clamped.
- **New-row entrance** is short-lived: the pending id lasts one `Motion.NewRow` after the store change; a row realised later appears without the slide.
- **Today progress** uses a whole percent, as the prototype does.
- **Calendar zooms from the keyboard** pass no origin (the transition's default 50 % 40 %).
- **Inbox scrollbar** — kept as the prototype's CSS defines it (8 px, inside the 12 px right padding); the reference image has none only because headless Chromium hides scrollbars.
- **Box-shadow order** — Avalonia paints a `BoxShadows` list last-on-top (the reverse of CSS), so the 1 px ring is listed last in `Border.dialog` / `.popover` / `.popover-sm`; overlay views set `ClipToBounds=False` so the ring and shadow outside the panel are drawn.
- **Task dialog popovers** — each popover is built on its first open and is in the tree only while open (removing it flushes a pending wheel commit); it stays at least 8 px inside the window, moving left/up by its overflow (at 1100×700 the Date popover covers its own pill). A popover is never taller than the window minus its 8 px edges; the Tag list scrolls inside it.
- **Task dialog save** — the first close decision wins and the draft saved is the one at the moment of Enter/Save; the store is written in `OnClosed`, after the exit animation. The primary button stays enabled without a title (the prototype uses `aria-disabled`), shows 0.45 opacity and only focuses the title.
- **Task dialog details** — the calendar's "Today" shows the current month and keeps the date; picking a duration also switches on "Set time"; Saturday and Sunday initials are dimmed in any week-start order; text boxes have no focus ring (prototype `.qa:focus{outline:none}`); focus returns to the pill when its popover closes.
- **Search palette** — Ctrl K / the title-bar button open an in-window palette in the task dialog's language: 52 px query row (magnifier, borderless "Search tasks" input), popover-style hit rows (priority glyph · title, struck when done · #tag · context), footer hint "↑↓ move · ↵ open · Esc close". Every keystroke re-runs `Projector.Search` (≤ 50 hits, 8 rows visible, the rest scroll; when more than 50 match, a muted line under the list says "More than 50 matches · keep typing to narrow") and selects the first hit; arrows clamp; Enter/click open the edit dialog; an empty query shows no list, no hits shows "No tasks found". Hits are not dimmed by the tag filter; rows are not focusable (focus stays in the query box).
- **Tray** — the icon exists only while "Keep running in the tray" is on and is created after the first frame (at once for a `--minimized` start). Menu: Open Doba / New task / Quit. With no tray available closing quits even when the setting is on, so the window never becomes unreachable (on Windows the tray is always reported available, so this applies off Windows and to `--demo`, which has no tray). Showing the window restores its last non-minimised state.
- **Shutdown** — the desktop lifetime uses explicit shutdown; the app ends through `AppLifecycle.Quit` (tray Quit, or close with the tray off). Pending writes are flushed on hide-to-tray, Quit, Exit and Windows session end (synchronously, at most 3 s); the database is disposed once.
- **Autostart** — the HKCU Run value is reconciled with the setting only on the default data location (never with `--demo` or `--data`): written if on and missing or pointing elsewhere, removed if off.
- **Global hotkey** — Ctrl+Alt+N is registered when the window has opened (not in demo); a refused registration is ignored; pressing it shows and activates the window and opens New task, keeping an already open dialog.
- **Carry-over** — when the setting is on (never in demo): open single-day tasks dated before today move to today, keeping time and everything else; multi-day tasks stay. Runs after the first frame and on day change through `TaskStore.UpdateMany`, which raises one `Batch` event. Idempotent, so no "last run" marker.
- **Daily backup** — when the setting is on (never in demo): after the first frame and on day change, on a background task, one at a time; a failure goes to Trace and is retried the next day.
- **System backdrop** — Mica on Windows 11, acrylic blur on Windows 10; while one is actually active the painted glows are hidden and the chrome tint is drawn over it; with none, the painted fallback is unchanged.
- **App icon** — the title-bar mark rendered at 16–256 px into `Assets/doba.ico`; used for the exe, the window and the tray.
- **`--selfcheck`** — a DemoData window that checks icon, window, backdrop level, OS animation setting, the hidden message window, hotkey register/unregister, the managed tray icon object create/show/remove (not whether Windows shows it) and autostart write/read/remove against `HKCU\Software\Doba\SelfCheck` (the Run key is only read), prints one line each (nine) and exits 0/1.
- **Closing during a save** — an overlay close that is already in its exit animation is completed before the window closes, hides to the tray, the session ends or the shell is disposed, so a just-saved task is never lost; a dialog that is merely open writes nothing.
- **Save with the Time popover open** closes the popover first, so a wheel value that has not settled yet is saved.
- **Schedule blocks** — block content copies the prototype's flex row: a trimmed title takes all the room left and the time range sits flush against the right padding; the range line is placed on the whole pixel row nearest to where Chromium paints it.
- **Row-dependent sub-pixel offsets in the references** (row-1 Week priority glyphs, Year row-1 item titles, the Day card-5 meta row, Today rows that are 1 px off as a whole) come from Chromium snapping fractional row offsets; the same element matches in the other rows, so they fall under "Whole-pixel layout" and are not fudged per row.
- **Calendar bars** — the 1 px border stands in for the CSS inset ring, so each bar's padding is the design's minus 1, and the fill is painted under the ring.
- **New-row entrance expiry** stays a real-time dispatcher timer (the injected clock is fixed in demo and tests, so it cannot measure the 360 ms window).
- **Content transitions** animate the screen host and the page h1 (title + subtitle) and, on Settings in/out, the sidebar that appears; breadcrumbs do not move (as in the prototype). Zoom origin is the click point when there is one, otherwise 50 % 40 %; Settings in/out use 50 % 30 %. Launch animates only the content area and starts at window-open without delaying the first frame. A new step invokes any pending swap at once and cancels what is running. The content area is clipped under the header (the prototype's `overflow: hidden`).
- **Sidebar collapse** — the sidebar column and the main panel's inset are laid out separately and each changes width once per toggle; the main panel slides 176 px by a composition translation for 340 ms ease-out. Measured: at most one Week re-projection and one main-panel layout per toggle (animating the width would re-lay out every frame). Cost: the content reflows once (start of a collapse, end of an expand) instead of continuously.
- **OS animation setting at run time** — `Motion.SystemAnimationsChanged` + `MotionSync` zero the XAML transition durations of live windows when animations go off and restore them when they come back; Animator-driven motion follows at once, and `StrikeText` reads its duration at every change. A transition built while animations were off stays instant until re-templated or restart (it errs only towards no animation).
- **Overlay motion** — shade in 220 ms / out 150 ms, window in 320 ms (opacity, translateY 10→0, scale 0.97→1) / out 150 ms, scaled around its real centre. Focus parks on the panel at once (keys never reach the page under the shade) and moves to the first input after the entrance; text typed during the entrance is buffered and delivered to that input. An overlay replacing the open one (search hit → dialog) keeps the shade and blur; only the new panel plays the entrance. During the entrance Esc closes and Backspace takes back a buffered character; other keys wait for the input (see "Keys during the overlay entrance").
- **Backdrop blur behind overlays** — reproduced (replaces "the dialog backdrop's 3 px blur is not reproduced"): a `BlurEffect` on the window content behind the overlay, σ = 3 px (`Size.Overlay.BackdropBlur`), its strength following the shade's opacity during the fades; nothing is redrawn while the shade is at rest. On the headless CPU raster it costs about 3× per frame during the two fades; on a real window (RX 9070 XT, 180 Hz) the blurred fades keep render p95 at 5.6–9.9 ms and max at 11.1–27.8 ms, none over 33 ms, so it stays (see "Backdrop blur kept after the real-window measurement"; integrated GPUs not measured).
- **Small motion choices** — schedule-block and Month-bar titles fade their colour over 300 ms like every other title; duration segments use the spec's 200 ms (the prototype's CSS says 150 ms); the shade uses the app's ease-out curve.
- **Keyboard matching** — shortcuts match the virtual key and fall back to the physical key under an IME, so N / G / I / T / K / digits work on the Ukrainian layout. Letters, digits and arrows act only with no modifier; Ctrl K needs exactly Ctrl; anything with Alt, Win or AltGr passes through.
- **Keyboard scope** (replaces "Shell keys") — N, G-chords, digits and arrows are text inside a text box and are ignored while an overlay is open; Ctrl K also works from a text box but not while an overlay is open. The G chord stays armed for 1500 ms. G I / G T use the section transition, also from Settings. 1–4 zoom the calendar at the current anchor, also from Inbox / Today / Settings. ← / → step the period in calendar views only and never while focus is in a text box, list box, slider, scrollbar or the time wheel. Esc closes a popover, then the overlay; otherwise nothing (it does not leave Settings). Arrows repeat; N, G, digits, Ctrl K, Esc and Space act once per press. The character of a key that fired a shortcut is never typed.
- **Tab order** — title-bar search, sidebar, page header (toggle, breadcrumbs, view switch, Today, ‹ ›, New task), content. Caption buttons are not tab stops (Windows convention). Week: day headers, bars, then cards column by column (checkbox, title, priority). Tab cycles inside an overlay; with a popover open it goes pill → popover → next pill. After a navigation focus stays on a control that still exists, otherwise moves to the content area. Keyboard focus in a scrolling list scrolls the neighbours into view, so Tab never skips virtualised rows.
- **`--perf`** — `frame-rendered-ms` is when the render thread finished the first frame with data; the time before `Main` comes from `Process.StartTime` (wall clock, diagnostic only). `--perf-idle-seconds N` and `--perf-scenario week` (with `--perf-rounds N`; followed by the overlay step) end the app when done. Frame statistics come from render-thread and UI-thread animation-frame callbacks — proxies, not GPU present times.
- **Database preload** — `Program.Main` opens, loads and indexes the database on a pool thread while Avalonia starts, after the data folder is claimed (never in demo or self-check).
- **Lists** — Inbox and Today are virtualised; the Day list is bounded by one day's tasks and search by 50 hits, so neither is.
- **Local runs never touch the real machine state** — tests use `PlatformServices.NoOp()` or fakes (or `Create` with an all-off `PlatformPlan`); `--demo` uses no autostart, hotkey or tray but the real read-only OS preferences and the click-driven shell (see "--demo platform"); a `--data` run registers the hotkey and shows the tray icon while it runs but never touches the Run key; the app is launched locally only with `--demo`, `--data <folder under artifacts\>` or `--selfcheck`.
- **Week starts on Sunday** — the Week view's two rows follow the configured week start: row 1 = its days 0–3, row 2 = days 4–6 plus the dimmed first day of the next week; Month columns and the dialog's mini calendar start on the same day (the design only shows Monday).
- **Next week (dialog)** — the Date popover's "Next week" is the first day of next week under the configured week start (a Sunday with a Sunday start); it can coincide with "Tomorrow", and both then show as selected, as in the prototype.
- **Search order** — open hits before done ones, then by date (undated last), then Id; the context column is "Inbox", the date ("Mon 16 Nov") or the span label ("20–22 Nov", "28 Oct – 2 Nov").
- **Completion sound** — the design only says "a soft click": a 40 ms mono click synthesized in code (two damped partials, 1 ms attack, no audio file) played asynchronously with `PlaySound`; only when a task is completed, not reopened.
- **Week geometry constants** — the Week grid sizes the card fitting depends on (header 86, lane 36, list padding, card gap, "+N more" reserve, minimum title width 80) live in `Screens/Week/WeekLayout.cs` and are used from XAML with `x:Static`, like Month's `MonthLayout.cs`, because the projection metrics and the view must share one value.
- **Task invariants** — the store normalises every task it loads, adds or updates: an End that is not after Date is dropped (single-day task), Time is dropped unless the task is dated and single-day, an undefined Priority becomes None (database rows are not validated on load; the store is the one gate).
- **Import ids** — ids above 2^53 are rejected (next id = max + 1 must stay exact and positive); `TaskStore.Add` uses checked arithmetic.
- **Import tags** — tag names and task tags are normalised like typed tags; names that collide after normalising are rejected; a task tag missing from the list is appended to it in task id order; a task tag that normalises to nothing ("#") means no tag.
- **Import JSON errors** — the message is our own sentence with the line number ("The file is not valid JSON (line N)."), never the framework's text (resource keys under NativeAOT).
- **Writer failures** (amends "Storage writes") — a burst refused by the database as a whole (BUSY, LOCKED, FULL, IOERR, READONLY, CORRUPT, CANTOPEN, NOTADB, NOMEM) fails as a whole without an op-by-op replay, counting each of its ops; only per-row errors (constraints, bad arguments) are replayed. Failed ops are not retried.
- **Backup temp files** — a `doba-yyyy-MM-dd.db.tmp` of any other day is deleted by the pruning; nothing else in `Backups/` is touched.
- **Days stepper** — "Lasts N days" is clamped to 1..max(14, current days): a longer imported span is never cut by "+", and "−" takes one day off.
- **Single instance** — one Doba process per data folder: `Program.Main` claims a per-session named mutex keyed on a hash of the full, case-folded data path before the preload starts. A second launch on the same folder sets a named event, so the running instance shows and activates its window (not for `--minimized`), and exits 0. `--demo` and `--selfcheck` take no claim; a crashed owner's abandoned mutex is taken over.
- **Strict command line** — unknown arguments, a missing or empty `--data`, a flag in a value position and out-of-range perf values are errors (stderr + usage, exit 2, nothing opened). Replaces "unknown arguments are ignored".
- **Data folder cannot be opened** — `StartupFailedException` names the folder and the reason; `Program.Main` shows a native error box (stderr only under `--perf`) and exits 3. Nothing in the folder is changed and no fresh database is created.
- **Failed writes** — every failed write is appended to `doba.log` in the data folder (restarted past 256 KB). The title bar shows "Changes not saved" in `Brush.Danger` until restart: the tooltip has the folder and the reason, a click opens the folder. This is not in the design; it appears only after a failure.
- **Opening size** — the window is 1600×1000 (the design's frame), or the screen's working area minus 16 px per side when that is smaller, never below the minimum 1100×700 (the smallest size the layout is built for), centred on the screen. Size, position and maximised state are not persisted.
- **Sidebar highlight timing** — the highlight, the current row and the settings tab change in the content swap (`MainViewModel.Present`), so on a section transition they slide with the new page's entrance, after the 130 ms exit, as in the prototype.
- **Midnight anchor** — Inbox and Today anchored at the old today move to the new day without a transition; calendars, and Inbox reached from a browsed calendar, keep their anchor.
- **Clock changes** — `WM_TIMECHANGE` (system time or time zone changed) clears .NET's cached local zone and re-reads today at once.
- **--demo platform** (refines "Local runs never touch the real machine state") — `--demo` uses no autostart, no hotkey and no tray, so closing a demo window quits. Its OS preferences (animations, backdrop; read only) and shell (open folder, sound; on a click) are the real ones. Tests check `PlatformPlan`, never the Windows objects.
- **G chord clock** — the 1500 ms are measured on the injected app clock's timestamps, which are real time in every mode (`FixedTimeProvider` fixes only the wall-clock time).
- **Year key items fit the measured cell** — each Year cell shows as many key items as fit below its header (`YearRoom`, measured after arrange); the items that do not fit are counted in "+N more" with the prototype's extra spans. At 1600×1000 the prototype's rows are unchanged.
- **Week short rows** — a Week row shows only the multi-day lanes that leave room for the card list's top padding and a "+N more" line (always all lanes at the design size). A bar in a hidden lane is counted in "+N more" of every day it covers, and "Nothing here" is not shown for such a day.
- **Day schedule aside** scrolls on its own like Today's, first centred on the now-line (today) or the earliest block, and again each time the cached Day view shows another day.
- **View switch re-entry** — returning from no level (Inbox / Today / Settings) places the indicator under the level without sliding and only fades it in; going to no level fades it out where it is.
- **Recycled list rows** show the new task's state at once (row dim, checkbox, title colour, strike); only changes of the same task animate (`SnapScope` around the data-context change).
- **Strike-through timing** — the strike fade reads its duration from `Motion` at every change, so turning Windows animations off or on while running applies to strikes too; the fade is attached only while animations are on.
- **Year stat** ends in an ellipsis in a narrow cell instead of running under "● NOW". Long tag names in the sidebar and the Tag popover and the page subtitle at 1100 px end in an ellipsis too.
- **Layout literals gate** — screen and control markup may contain only 0 and ±1 px (hairline rules, one-pixel nudges), star weights and Auto; every other spacing, size, radius, stroke or font size is a token. The colour / duration / easing / delay scan covers all of `src/Doba.App` except `Theme/Tokens.axaml`, `Theme/AccentPalette.cs`, `Motion/Motion.cs`, `Motion/MotionTimes.cs` and `Platform/`.
- **Palette tokens** — `Color.Chrome.Base` and the overlay shadows (`Shadow.Popover`, `Shadow.PopoverSmall`, `Shadow.Dialog`, `Shadow.Ring.Emphasis`) are Dark-palette tokens; the chrome tint is re-applied when the theme variant changes.
- **Overlay focus return** — it runs right after the close turn (after `OnClosed` has written the store), so a deleted card, or one moved to another day, falls back to New task. The focus ring is shown on the opener or the fallback only if the opener had keyboard focus (`:focus-visible`) when the overlay opened. An overlay opened before focus returns keeps the original return target.
- **Keys during the overlay entrance** — Esc closes the overlay; text is buffered; Backspace removes the last buffered character; Enter, arrows and other keys do nothing until the first input has focus, so a quick Enter never saves a half-typed task.
- **Dialog across midnight** — saving an edit whose date and span were not changed keeps the stored date (single-day tasks only, which are the only ones carry-over moves). A new task still on its default today follows the day change. The labels and the calendar's today follow `DayChanged`. A date the user picked is never moved.
- **Dialog label placement** — single-line labels whose box is exact but whose ink sat 1 px low (pill labels, Cancel, Priority / Tag / search rows) take `Space.Dialog.Raise` (0,−1,0,1: exactly 1 px up, size unchanged); the footer hint takes `Space.Dialog.Lift`. Checked against the references by `TaskDialogLabelPlacementTests`.
- **GC gen0 budget** — the NativeAOT build embeds `GCgen0size` = 8 MB (`IlcArg --runtimeopt` in `Doba.App.csproj`; `DOTNET_GCgen0size` overrides it). Dense compact Week, render thread, two runs each, worst frame / frames over 33 ms: default (~30 MB) 68 / 63 ms, 4 / 5 (7 GCs, all gen1, 247 / 228 ms pause); 4 MB 27.5 / 44, 0 / 1 (45 GCs); 6 MB 161 (one outlier) / 33.3, 7 / 1; 8 MB 28.6 / 27.9, 0 / 0 (32 GCs, 384 / 380 ms); 12 MB 33.4 / 36.3, 1 / 2; 16 MB 109.2 / 37.6; 32 MB 79.4 / 48.6; 64 MB 73.1 / 94.9; non-concurrent 107.4 / 104.4; GCConserveMemory=5 96.5 / 85.5. Cost of 8 MB: one (demo) or two (10k) collections at startup, warm start +0–11 ms (demo) and +18–24 ms (10k); idle working set within 1–2 MB. Chosen because the 400 ms startup budget keeps a wide margin while 60–110 ms render stalls are visible. Revert = delete one ItemGroup.
- **Startup with a no-GC region** (tested, rejected) — `GC.TryStartNoGCRegion(64 MB)` from Main to the first frame removes the startup cost of the 8 MB budget, but idle private bytes go from ~151 to 278 MB (10k).
- **Week frame budget load** — the "~40 cards" case is `db-dense-compact`: 10,000 tasks plus a filled current week in compact density, 38 cards + 5 bars at 1600×1000. Comfortable density holds at most 29 + 5 at this size, so no comfortable dataset can reach 40.
- **Backdrop blur kept after the real-window measurement** — on the GPU (RX 9070 XT, 180 Hz) the blurred fades keep render p95 at 5.6–9.9 ms and max at 11.1–27.8 ms, with 1–2 frames over 16.7 ms per 8 fades; without blur, max 6.1–16.7 ms. No fade frame is over 33 ms. The CPU-raster cost does not carry over to the GPU.
- **Startup reporting** — three kinds of number: warm (`scripts/perf.ps1` default; the first launch after publish is also warm), partly cold (`-ColdExeRuns`: exe from an uncached copy, antivirus scan included; 1.0–1.5 s on the dev PC) and cold after a reboot (`-PrepareCold`, reboot, `-Cold`). Mid-range hardware has not been measured.
- **Overlay perf step** — `--perf-scenario week` also runs the overlay step (New task dialog, 8 cycles with blur, 8 without, alternating; nothing is written). It needs the window in front: a covered window records no render frames (shown as n/a).
- **Week lane cap in Core** (moves "Week short rows" out of the App) — `WeekMetrics.VisibleLanes` decides the lanes shown (room = row − header − list padding − the "+N more" line); a hidden bar counts in "+N more" of each day it covers; the card list gets the room of the visible lanes.
- **Week fit measurement** (amends) — the App fits cards with `WeekMetrics.TaskCardHeight` (per task: title, tag, time, priority, per density); the title-only height is only the bare-card fallback.
- **Month third lane** (extends the prototype's `if (lane > 1) return`) — a span that needs a third lane is still not drawn, but it is counted in "+N more" of every day it covers in that week, so a task never vanishes from the Month view; the cell leads to the Day view, which lists it. Weeks with two lanes or fewer are unchanged.
- **Year fit in Core** (replaces the App-side rule) — `YearMetrics` (room, item height, gap, more-line height) is an input of `Projector.Year`; the view measures each cell's room and the view-model re-projects when a room changes. Without metrics the prototype's rows are listed.
- **Progress bars** (replaces "Today progress uses a whole percent") — Today, Week cells and Year months use a whole percent, `Math.round(done / n · 100)` as in the prototype, computed in Core.
- **Display labels** — the screens' texts and accessible names ("+N more", "W46", "Open …", upper-cased weekday and stat labels, "Mark done: …", "Priority: … — change for …", "Move to today: …") are computed properties of the Core records; view-models copy them.
- **Dialog transitions in Core** — picking a duration (also switches on "Set time"), a priority or a tag (closes the popover), toggling a popover and the calendar's "Today" are pure `TaskDialog` functions; the unused `StepDate` / `StepTime` are removed (the prototype's `ntDayPrev` / `ntTimePrev` are not bound in its markup).
- **Storage retries** (amends "Writer failures") — writes refused with BUSY, LOCKED, IOERR or FULL are kept in order and applied first by the next burst or the next flush after the failure was reported; permanent errors are dropped; on close the kept writes get one more attempt and anything still unwritten is reported.
- **Week cards across week changes** — a cell's cards are reused by position when the week changes (re-pointed at the new task with no state fade) and stay keyed by task id within a week; a card holding keyboard focus is replaced instead. Allocation per week step fell from 13–16 MB to about 5 MB.
- **Exit drain bound** — desktop Exit waits at most 5 s for the final flush and database close; on a timeout it logs and the process ends (session end keeps its own 3 s bound).
- **Export / import messages** — fixed sentences per failure kind, never the exception's text; "Imported N tasks." appears only after the flush, and a failed write shows the failure instead.
- **Readable framework errors** — `UseSystemResourceKeys=false` for the NativeAOT build: real .NET exception messages in `doba.log` and the startup error box, for +58 KB on `Doba.exe` and no measurable startup cost.
- **Skia GPU cache cap** — 24 MB (`SkiaOptions.MaxGpuResourceSizeBytes`; Avalonia's default is about 28 MB): idle working set −3 MB (demo) to −8 MB (10,000 tasks) with frame times unchanged; caps of 20 MB and below doubled render p95 on dense weeks. Measured at 1600×1000 only.
- **Segmented label placement** — only the Fill variant (the Time popover's mode switch) is raised 1 px; the Settings rows' remaining sub-pixel offset comes from the 71 px row pitch (the reference's first row is 70 px) and is accepted.
- **Tray icon attachment** — the tray icon is added to the application's `TrayIcon.Icons` collection (in Avalonia 12 that is what creates the native icon; a standalone `TrayIcon` never appears). If no native icon results, `ITrayIcon.IsSupported` turns false and closing the window quits instead of hiding it.
