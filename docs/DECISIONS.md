# Decisions

One line per decision, newest last. Format: **topic** — decision (reason).

- **Design source** — `docs/design/design-reference.dc.html` is the prototype's `Main.dc.html` taken from the published "Todo for Windows" design artifact (the repo did not contain it); the other boards only set `start-view`.
- **.NET SDK install** — SDK 11.0.100 installed from Microsoft's Debian 12 package feed (packages.microsoft.com) because `builds.dotnet.microsoft.com` / `dot.net` downloads are blocked by the VM's network allowlist.
- **Solution format** — classic `Doba.sln` (the brief names it) rather than the new `.slnx` default.
- **Test runner** — Microsoft Testing Platform (`global.json` `test.runner`), required by the .NET 10+ SDK for xunit v3 projects.
- **xunit version** — `xunit.v3.mtp-v2` 3.2.2, not 4.x: `Avalonia.Headless.XUnit` 12.1.6 is compiled against xunit.v3 3.2.2 and fails discovery with `MissingMethodException` under 4.0.3. All test projects use the same version.
- **CA1716 off** — VB-keyword clash warnings (`Get`, `Date`, `To`) are noise in a C#-only codebase.
- **Avalonia telemetry** — `AVALONIA_TELEMETRY_OPTOUT=1` in CI and docs; the app itself makes no network calls.
- **Ids** — `long` ids assigned by the store as max existing Id + 1; Id order replaces the prototype's array order as the final sort key (a deleted newest Id may be reused, which is harmless for upsert persistence).
- **Durations** — `DurationMinutes = 0` means "unspecified"; the timeline treats it as 30 min (prototype `dur || 30`); the dialog defaults to 60.
- **Week numbers with Sunday start** — label = ISO week of the Monday inside the displayed 7-day week.
- **Name** — "Doba" replaces the design's working title "Todo" everywhere (title bar, settings footer "Doba 0.1 · local only", data folder `%LOCALAPPDATA%\Doba`).
- **Storage writes** — single background writer over an unbounded Channel; bursts commit in one transaction; failed bursts replay op-by-op; errors surface from the next `FlushAsync` / `WriteFailed` event.
- **Storage reads** — `Load()` reads tasks through SQLitePCL's low-level API (halves 10k load time vs SqliteDataReader).
- **JSON enums** — camelCase strings (`"asap"`, `"sunday"`); import validates and reports JSON paths in `FormatException`.
- **P/Invoke style** — platform code uses `DllImport` with only blittable signatures (no strings, no SetLastError) instead of `LibraryImport`, avoiding `AllowUnsafeBlocks`; under NativeAOT these bind directly with no marshalling stubs.
- **Hotkey / setting-change messages** — received by Doba's own hidden window rather than Avalonia's `Win32Properties.AddWndProcHookCallback`, whose shared callback chain lets the last subscriber overwrite earlier results (e.g. title-bar hit testing).
- **Autostart** — HKCU Run value `Doba` = `"<exe>" --minimized`; the app starts hidden in the tray with that flag.
- **Overdue span label across months** — "28 Oct – 2 Nov" (the prototype would print "28–2 Nov").
- **Tag normalisation** — whitespace left after stripping '#' is trimmed ("# deep work" → "deep-work").
- **Store no-ops** — mutations of unknown Ids and identical updates raise no event and write nothing.
- **Golden tests** — Core projections are checked against fixtures generated by running the prototype's own script under Node; fixtures are committed so tests do not need Node.
- **No stock theme** — no Fluent/Simple theme package; base templates for the few stock controls we use are ours (`Theme/Controls/Base.axaml`).
- **Animator** — content animations are explicit composition animations (opacity, translation, scale offsets from layout); cancel/reset always restores opacity 1 and identity. Zoom blur not implemented (optional in the spec).
- **Hover brightness(1.2)** on bars/blocks is approximated with a 4 % white overlay; the dialog backdrop's 3 px blur is not reproduced (shade colour only).
- **Own ToggleSwitch** — subclass of ToggleButton so the knob moves by render transform, not layout.
- **CI cost** — owner asked for minimal GitHub Actions use: one windows-latest job, triggered only by `workflow_dispatch` or a pull request to main (docs-only changes skipped), concurrency-cancelled, 30-min timeout; Linux build/test/screenshots run locally in the dev VM instead.
- **Import** replaces all tasks, tags and settings with no confirmation (the design has none); result/error shown inline under "Export & import".
- **Theme "System"** is stored but rendered as Dark (no light palette yet).
- **Strike-through** — Avalonia cannot bind a TextDecoration stroke brush per state cheaply, so done titles toggle the strike and fade the text colour (Motion.Strike); the strike line itself does not fade from transparent.
- **Inbox virtualisation** — per-group ItemsControls with VirtualizingStackPanel inside one page ScrollViewer (Avalonia 12 virtualises against the effective viewport), so both columns still scroll together as designed.
- **Week fit measurement** — the view reports each row's height; card heights come from shaping the title with the real font at the real column width (≤2 lines), per density; Core's `WeekMetrics.CardHeight` receives the measured map.
- **Week compact** — compact density shows as many cards as actually fit (the prototype's compact render reuses its fixed 403 px heuristic).
- **Windows-first from 2026-11-18** — the build continues on the owner's Windows 11 PC, so build, tests, headless screenshots, NativeAOT `win-x64` publish and `--perf` are all run locally; the local AOT smoke is `win-x64`, not `linux-x64`.
- **No extra Actions runs** — owner's instruction: test everything locally. No `workflow_dispatch` runs; the single CI run is the one the final pull request into `main` triggers.
- **Overlays are in-window panels** — the task dialog, its popovers and the search palette are hosted by `Shell/OverlayHost` inside the main window, not Avalonia `Popup` windows: headless frame capture does not include popup top-levels, and one window keeps focus handling simple.
- **Screenshot writing is opt-in** — tests write PNGs to git-ignored `artifacts/screenshots/` unless `DOBA_SCREENSHOTS=1`, which refreshes `docs/screenshots/` (parallel worktrees would otherwise rewrite tracked binaries on every test run).
- **Sidebar collapsed state** is kept in memory only (the prototype does not persist it either).
- **Search hits** always open the task's edit dialog; the palette never navigates.
- **Content swap** — `MainViewModel` raises `Navigated`, then hands the swap to `ContentSwapper`, which the window points at `ShellComposition.Transitions.Run`; screen, header and sidebar all change inside the swap, so on section transitions the title changes with the content (as in the prototype).
- **Screen views are cached** — a screen's view is created on first visit and then kept in the tree with `IsVisible=false`, so a transition never rebuilds a visual tree.
- **Overlays** — opening an overlay while one is open replaces it at once (search hit → edit dialog); clicking the shade does nothing (the prototype's shade has no handler); focus moves into the overlay after its first layout and returns to the element that had it, or to New task if that is gone.
- **Shell keys** — N only when no overlay is open, no text box has focus and New task is visible; Ctrl K ignored while an overlay is open.
- **Caption buttons** carry Avalonia's window-decoration element roles and also plain click handlers; maximise keeps one glyph (the design has no restore glyph).
- **Backdrop glows** — the design's three blurred blobs are painted as radial falloffs calibrated against the reference pixels; nothing is blurred at run time.
- **Header title** — title and subtitle are two text blocks (Avalonia applies letter-spacing per block); offsets were measured against the reference and stored as `Space.Shell.*` tokens.
- **Add-tag row in the rail** — collapsing the sidebar while the tag input is open creates a non-empty name (same as losing focus); in the rail "+" is disabled.
- **Many tags** — the tag list scrolls so Collapse/Settings stay pinned at the bottom (the prototype clips).
- **Sidebar counts** are always shown, including 0, and never dimmed by the tag filter.
- **Settings tab label** — the sidebar says "Shortcuts", the page title says "Keyboard shortcuts" (both as in the prototype).
- **Month cells** are reconciled by week position and column, not by date, so changing month updates ~42 cells in place.
- **Month "+N more", chips and bars** are not interactive on their own; the click goes to the day cell (prototype: `pointer-events: none`).
- **Month geometry** used by both the projection and the view (26 header, 40 W-column, 34 day number, 24 lane) lives in `Screens/Month/MonthLayout.cs`.
- **Day rows** — Day span rows and cards are their own controls (`DaySpanRow`, `DayCard`): the Day design's sizes and two-row card differ from the week bar and card.
- **Day "Add task"** passes the shown day and is labelled just "Add task" (the prototype's `addLabel` is unused in its markup).
- **Time wheel emphasis** — the selected number is laid out at 19 px once per commit and the 15→19 growth is a render-transform scale, so nothing is re-laid out per frame; emphasis follows the committed value, not the row passing under the band.
- **Time wheel commit** — fires after 120 ms of stillness following a user move, even if the index ends up unchanged (in the prototype any scroll switches on "Set time"); the 120 ms wait is not an animation and stays when OS animations are off; a pending commit is flushed if the wheel is removed (quick "Done"). Smooth scrolling uses `Motion.Slide`; no fling momentum.
- **Reference PNG vs prototype source** — where a reference image shows an artefact of how the prototype was rendered (Month span bars drawn as loose text under the row, Week column separators and the next-week hatch missing, no scrollbars in headless Chromium), the prototype source wins.
- **Text rendering** — every window draws text with grayscale antialiasing and no hinting, like the prototype (`-webkit-font-smoothing: antialiased`). Glyph boxes match the references to the pixel; our stems still carry a little more ink (Skia's text gamma, not configurable in Avalonia 12.1.6). Font weights are not altered to compensate.
- **Whole-pixel layout** — Avalonia rounds each measured size up where Chromium carries fractions, so a few stacks land 1 px off the reference (Inbox/Today section rhythm, 4th Day card onward, settings rows 71 vs 70.7 px, key caps 19 vs 18.3 px). Accepted rather than fudged with per-element offsets.
- **Segmented controls and text buttons** come out 1–2 px wider than the reference when they hold several labels (each label's width rounds up to a whole pixel); unrounded text layout would blur the pill edges, so this stays.
- **Checkbox ring** — the CSS 1.5 px ring is snapped down to whole device pixels (1 px at 100 %), as Chromium paints it.
- **Strike-through** — `StrikeText` paints its own always-present 1-device-px line on a whole pixel row and only animates its colour (replaces the earlier "toggle the decoration" decision wherever `StrikeText` is used).
- **Glyph centring** — icons and the priority glyph round half-pixel centring offsets up, as Chromium does.
- **Calendar track edges** — column edges at `round(i·W/n)`, row edges at `floor(j·H/m)`, reproducing the reference's snapping.
- **Month rows** use the measured body height − 4 px (the prototype hard-codes 832 inside an 836 px body); when a week row leaves under 26 px below its lanes, the cell shows "+N more" for all its tasks in the day-number row.
- **Week cards** — titles break only between words; when tag + time would leave the title under 80 px the tag is hidden (priority and time stay) and "+N more" fitting uses the same rule. The screen builds no cards before its first measure pass. Cells are reused across week changes.
- **Space** completes the focused task from any button of a list row or week card (the checkbox keeps its native Space); Enter keeps the focused button's own action; key repeat does not toggle again.
- **Today schedule aside** scrolls on its own when the content area is shorter than the 812 px timeline, first centred on the now-line; at 1600×1000 it does not scroll.
- **Now-line** is shown only between 07:00 and 23:00; outside the grid it is hidden, not clamped.
- **New-row entrance** is short-lived: the pending id lasts one `Motion.NewRow` after the store change; a row realised later appears without the slide.
- **Today progress** uses a whole percent, as the prototype does.
- **Calendar zooms from the keyboard** pass no origin (the transition's default 50 % 40 %).
- **Inbox scrollbar** — kept as the prototype's CSS defines it (8 px, inside the 12 px right padding); the reference image has none only because headless Chromium hides scrollbars.
- **Box-shadow order** — Avalonia paints a `BoxShadows` list last-on-top (the reverse of CSS), so the 1 px ring is listed last in `Border.dialog` / `.popover` / `.popover-sm`; overlay views set `ClipToBounds=False` so the ring and shadow outside the panel are drawn.
- **Task dialog popovers** — each popover is built on its first open and is in the tree only while open (removing it flushes a pending wheel commit); it stays at least 8 px inside the window, moving left/up by its overflow (at 1100×700 the Date popover covers its own pill).
- **Task dialog save** — the first close decision wins and the draft saved is the one at the moment of Enter/Save; the store is written in `OnClosed`, after the exit animation. The primary button stays enabled without a title (the prototype uses `aria-disabled`), shows 0.45 opacity and only focuses the title.
- **Task dialog details** — the calendar's "Today" shows the current month and keeps the date; picking a duration also switches on "Set time"; Saturday and Sunday initials are dimmed in any week-start order; text boxes have no focus ring (prototype `.qa:focus{outline:none}`); focus returns to the pill when its popover closes.
- **Search palette** — Ctrl K / the title-bar button open an in-window palette in the task dialog's language: 52 px query row (magnifier, borderless "Search tasks" input), popover-style hit rows (priority glyph · title, struck when done · #tag · context), footer hint "↑↓ move · ↵ open · Esc close". Every keystroke re-runs `Projector.Search` (≤ 50 hits, 8 rows visible, the rest scroll) and selects the first hit; arrows clamp; Enter/click open the edit dialog; an empty query shows no list, no hits shows "No tasks found". Hits are not dimmed by the tag filter; rows are not focusable (focus stays in the query box).
- **Tray** — the icon exists only while "Keep running in the tray" is on and is created after the first frame (at once for a `--minimized` start). Menu: Open Doba / New task / Quit. With no tray available closing quits even when the setting is on, so the window never becomes unreachable. Showing the window restores its last non-minimised state.
- **Shutdown** — the desktop lifetime uses explicit shutdown; the app ends through `AppLifecycle.Quit` (tray Quit, or close with the tray off). Pending writes are flushed on hide-to-tray, Quit, Exit and Windows session end (synchronously, at most 3 s); the database is disposed once.
- **Autostart** — the HKCU Run value is reconciled with the setting only on the default data location (never with `--demo` or `--data`): written if on and missing or pointing elsewhere, removed if off.
- **Global hotkey** — Ctrl+Alt+N is registered when the window has opened (not in demo); a refused registration is ignored; pressing it shows and activates the window and opens New task, keeping an already open dialog.
- **Carry-over** — when the setting is on (never in demo): open single-day tasks dated before today move to today, keeping time and everything else; multi-day tasks stay. Runs after the first frame and on day change through `TaskStore.UpdateMany`, which raises one `Batch` event. Idempotent, so no "last run" marker.
- **Daily backup** — when the setting is on (never in demo): after the first frame and on day change, on a background task, one at a time; a failure goes to Trace and is retried the next day.
- **System backdrop** — Mica on Windows 11, acrylic blur on Windows 10; while one is actually active the painted glows are hidden and the chrome tint is drawn over it; with none, the painted fallback is unchanged.
- **App icon** — the title-bar mark rendered at 16–256 px into `Assets/doba.ico`; used for the exe, the window and the tray.
- **`--selfcheck`** — a DemoData window that checks icon, window, backdrop level, OS animation setting, the hidden message window, hotkey register/unregister, tray create/remove and autostart write/read/remove against `HKCU\Software\Doba\SelfCheck` (never the Run key), prints one line each and exits 0/1.
- **Closing during a save** — an overlay close that is already in its exit animation is completed before the window closes, hides to the tray, the session ends or the shell is disposed, so a just-saved task is never lost; a dialog that is merely open writes nothing.
- **Save with the Time popover open** closes the popover first, so a wheel value that has not settled yet is saved.
- **Schedule blocks** — block content copies the prototype's flex row: a trimmed title takes all the room left and the time range sits flush against the right padding; the range line is placed on the whole pixel row nearest to where Chromium paints it.
- **Row-dependent sub-pixel offsets in the references** (row-1 Week priority glyphs, Year row-1 item titles, the Day card-5 meta row, Today rows that are 1 px off as a whole) come from Chromium snapping fractional row offsets; the same element matches in the other rows, so they fall under "Whole-pixel layout" and are not fudged per row.
- **Calendar bars** — the 1 px border stands in for the CSS inset ring, so each bar's padding is the design's minus 1, and the fill is painted under the ring.
- **New-row entrance expiry** stays a real-time dispatcher timer (the injected clock is fixed in demo and tests, so it cannot measure the 360 ms window).
- **Local runs never touch the real machine state** — tests and `--demo` use no-op platform services; the app is launched locally only with `--demo`, `--data <folder>` or `--selfcheck`.
